# Agent Dial behavior contract

## Objective

Fork the [OpenHarness device](https://github.com/autonomous-ai/openharness/tree/468979983431cbd86905d97fd211d588fa1d880a/devices/harness-device) onto the M5Stack Stopwatch and make it work with any coding-agent harness.

The dial shows every running agent session on your desk: which ones are working, what each one last said, and which one needs you.
From the dial you answer an agent's question, approve or deny a tool, stop a turn, and speak a new task.

This is an honest fork.
It keeps the upstream firmware's shipped behavior (its screens, gestures, timings, sounds, frame format, and message names) wherever the Stopwatch and a harness-neutral host allow.
Every change is listed in *Provenance* with its reason.
Upstream is MIT-licensed, © 2026 Autonomous, Inc.; its notice is kept in [LICENSE-OPENHARNESS](LICENSE-OPENHARNESS).

## Shared platform contract

The target is the M5Stack Stopwatch with a corrected 468 × 466 drawable panel, rotation 0, x offset 6, and y offset 0.
BtnA is physical left and BtnB is physical right with the lanyard down.
The dial loads `espt-touch/record` after panel geometry is corrected, accepts safe version-1 and version-2 records, and maps every raw touch through the complete shared warp.
It adds no lesson-specific touch offset, scale, or axis swap.
Settings exposes the shared guided calibration: a successful commit applies immediately, and cancel keeps the active map.
App-only updates at `0x10000` preserve NVS.
A merged image written at `0x0` is a fresh install that can erase calibration, Wi-Fi, and pairing, and must be labeled that way.

## System

```text
pi session ──── extension ─┐
Claude Code ─── hooks ─────┼─► hub (~/.agent-dial/hub.sock) ─── USB frames ───► Stopwatch
any script ──── agent-dial ┘                                                       ▲
                     └──────────── direct Wi-Fi (HTTP + bearer token) ─────────────┘
```

- **Adapter:** reports one harness's sessions and carries answers and commands back. It must never throw into the harness, block a turn it wasn't asked to block, or delay a harness by more than 250 ms when the dial is absent.
- **Hub:** one local process that owns the serial port, merges every adapter's sessions, runs speech-to-text, and provisions the board over USB.
  - The first adapter that needs it and finds a USB board starts it detached.
  - It exits after 5 minutes with no clients and no board.
  - It opens no listening network port.
- **Direct Wi-Fi:** an adapter that cannot reach a hub, but holds a pairing record, talks HTTP to the board itself. No process runs on the computer for this path.
- **Device:** merges sessions from the hub and from direct clients, renders the dial, and records voice.

## Session model

A session is one agent conversation in one harness.
Every message about a session carries its `id`: printable ASCII, 1–47 characters.
Adapters prefix their ids with the harness name (`pi:`, `claude:`, `cli:`) so two harnesses cannot collide, keeping the tail of an id that would overflow. Direct Wi-Fi has no hub to do it for them.

Each session declares its **capabilities** in `hello`:

| Capability | Meaning | Dial affordance when absent |
| --- | --- | --- |
| `answer` | The adapter can deliver an answer to a multiple-choice question | No questions arrive |
| `approve` | The adapter can deliver an allow/deny decision for a tool call | No approvals arrive |
| `stop` | The adapter can interrupt the running turn | Back on a working tile toasts `Can't stop this from here` |
| `prompt` | The adapter can start a turn with new text | The tile's Voice button is hidden; Enter toasts `Can't send to this harness` |

An approval is a question with one key, `decision`, and the options `Allow` and `Deny`.

### Adapter capabilities

| Harness | Adapter | Capabilities | Mechanism |
| --- | --- | --- | --- |
| pi | extension in `~/.pi/agent/extensions/agent-dial/` | `stop`, `prompt`, and `approve` when `AGENT_DIAL_APPROVE=1` | `ctx.abort()`, `pi.sendUserMessage()`, and a blocking `tool_call` handler. pi has no built-in question tool, so it declares no `answer`. |
| Claude Code | command hooks running `agent-dial claude <event>` | `approve` | The `PermissionRequest` hook returns `hookSpecificOutput.decision.behavior` = `allow` or `deny`. Claude Code documents no way for a hook to answer `AskUserQuestion`, interrupt a turn, or inject a prompt, so the adapter declares none of those. |
| Any program | `agent-dial` CLI | whatever the caller passes | `agent-dial ask` blocks and prints the chosen option |

An adapter may only declare a capability after the mechanism has been exercised against that harness's installed version.
The capabilities in this table are a ceiling, not a promise.

## Transports

The vocabulary in *Messages* is the same on every link.

### USB (hub ↔ device)

Framing is upstream's, with the fork's magic, little-endian throughout:

```text
A5 45 | ver:u8 = 1 | type:u8 | len:u16 | payload[len] | crc16:u16
```

- The CRC is CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF, no reflection, no final xor) over `ver` through the end of the payload. The check value for `"123456789"` is `0x29B1`.
- `len` is at most 8192. The encoder refuses a larger payload rather than truncating it.
- Types: `0x01` JSON (UTF-8 object with a `t` field), `0x02` PCM (device → hub), `0x04` LOG (device → hub, one line, at most 511 bytes), `0x05` SHOT (device → hub, framebuffer bytes).
  - `0x03` is reserved for firmware and unused.
  - An unknown type is passed up and counted, never treated as corruption.
- **Resync:**
  - bytes before a magic are discarded and counted;
  - a trailing `A5` is kept in case `45` follows;
  - a length over 8192 or a CRC mismatch drops one byte and resumes the hunt;
  - a full buffer drops its oldest byte.
- The device and hub each serialize their writes, so a frame never lands inside another.
- The device's USB CDC write timeout is 0 outside a framebuffer dump. A closed host port must never stall the dial.
- Until a `welcome` arrives, the port is a plain console. After it, every device log line travels as a LOG frame.
- `tests/vectors/dial_frame.txt` is the shared codec vector file. `tests/gen_frame_vectors.py` generates it from this description rather than from either implementation.

### Direct Wi-Fi (adapter ↔ device)

- **Credentials:** the board joins the network stored in the shared ESPtember Wi-Fi slot (Preferences `day22`: `ssid`, `pass`) with modem sleep enabled.
- **Discovery:** it advertises `agent-dial-<last 4 hex of MAC>.local` and `_agent-dial._tcp`, and serves HTTP on port 47838.
- **Pairing:** the hub pairs the board over USB and writes `~/.agent-dial/device.json` (mode 600) with `{id, ip, host, port, token}`. Adapters read that file for direct mode.
- **Requests:** every request carries `Authorization: Bearer <token>`.
  - A missing or wrong token answers `401` and changes nothing.
  - The comparison is constant-time.
- **The one endpoint:** `POST /v1/exchange` with `{"client":"<adapter instance id>","messages":[…adapter → hub messages…]}`.
  - The device applies the messages as if the hub had relayed them.
  - It answers `{"ok":true,"commands":[…]}` with every queued hub → adapter message for the sessions this client registered, and each message is delivered once.
- **Polling:** adapters poll with an empty `messages` array every 1 s while one of their sessions has an open question or a running turn, and every 5 s otherwise.
- **Expiry:** a direct session with no exchange for its `ttl` (default 30 s) is removed.
- **Security:** traffic is authenticated but not encrypted. Anyone on the network who captures a request learns the token. Pairing again (`agent-dial pair`) replaces it. This is weaker than Day 34's HMAC handshake, and it is recorded under *Roadmap*.
- **No provisioning over Wi-Fi:** `wifi`, `pair`, and `forget` are USB-only. Over HTTP they answer `403`.
- **Voice** needs the hub, because speech-to-text runs on the computer. In direct mode the Voice button toasts `Voice needs the hub`.

### Adapter ↔ hub

Newline-delimited JSON on the Unix socket `~/.agent-dial/hub.sock`, overridable with `AGENT_DIAL_SOCKET`.
An adapter tries the hub first; with neither a hub nor a USB board, it tries direct Wi-Fi; with neither, it stays quiet and retries every 5 s.

## Messages

Every JSON message has a string `t`.
The hub accepts fields flat; the device also accepts them nested under `p`, as upstream does.

### Adapter → hub, or direct to the device

| `t` | Fields | Meaning |
| --- | --- | --- |
| `hello` | `id`, `name`, `harness`, `cwd?`, `caps[]`, `ttl?` | Register or rename a session. `name` defaults to the cwd basename. `ttl` (seconds) marks a session whose reporter does not hold a connection open, such as a Claude Code hook. |
| `turn.started` | `id`, `text` | A turn is running. `text` is a redacted activity line such as `$ npm test` or `editing src/app.ts`. A repeat updates the line. |
| `turn.done` | `id` | The turn ended with nothing to show. |
| `turn.error` | `id`, `message` | The turn failed. |
| `summary` | `id`, `text` | The turn finished. `text` is the recap (the first 160 characters of the final assistant message, redacted). |
| `question` | `id`, `requestId`, `questions[{key,q,multi,options[]}]` | Ask the dial. |
| `question.close` | `id`, `requestId` | The question was answered elsewhere, or it expired. |
| `bye` | `id` | The session ended. |

Hub-only diagnostics: `status`, `release` (free the port for 30 s), `pause {seconds}` / `resume`, `monitor`, `raw {msg}`, `wifi {ssid?}`, `pair`, `forget`.

### Hub → adapter, or queued commands from the device

| `t` | Fields | Meaning |
| --- | --- | --- |
| `answer` | `id`, `requestId`, `answers{key: string}` | The person chose. Multi-select answers join with `", "`, as upstream does. |
| `turn.send` | `id`, `text` | Start a turn with this text. |
| `turn.stop` | `id` | Interrupt the running turn. |

### Hub → device (JSON frames)

Upstream names, minus product-specific fields:

| `t` | Fields | Device behavior |
| --- | --- | --- |
| `welcome` | `proto: 1`, `app: "agent-dial"`, `host: {name}` | Starts the session, turns on log framing, and asks for `agents.list`. |
| `ping` | none | Every 5 s. The device replies `pong`. |
| `agents.begin` / `agent` / `agents.end` | `agent`: `id`, `name`, `harness`, `caps[]`; `agents.end`: `total` | Replaces the hub-owned sessions in list order. At most 16 sessions exist across all sources. |
| `focus` | `id` | Moves the carousel without echoing `focus` back. |
| `turn.started` / `turn.done` / `turn.error` / `summary` / `question` / `question.close` | as above, plus `summary.quiet?` | See *Behavior*. |
| `notif.replace` | `items[{id,summary,question}]`, at most 8 | Replaces the drawer, used once per attach. |
| `notif.seen` | `id` | Removes that session's row. |
| `voice.transcript` | `id`, `text` | The words were routed to `id`. An empty `id` means no session took them. |
| `voice.error` | `message` | Releases the voice overlay and toasts `message`. |
| `toast` | `text` | Shows a toast. |
| `pair` / `wifi` / `forget` | `token` (64 hex) / `ssid`, `pass` / none | USB provisioning. `wifi` credentials are never logged or echoed. |

### Device → hub (JSON frames)

`hello {fw, product: "agent-dial", proto: 1, hw: "m5stack-stopwatch", mac, wifi: none|saved|connected, ip, paired, key}` is sent every 2 s without a session and every 15 s with one.
`key` is the first 8 hex of SHA-256(token), or `-`.
The hub answers every `hello` with `welcome`, and pairs an unpaired board or one whose key does not match its record.

The device also sends `pong`, `agents.list`, `focus {id}`, `agent.open {id, reason?}`, `answer`, `turn.stop {id}`, `voice.begin {id?, lang, sr: 16000}`, PCM frames, `voice.end`, `voice.abort {why}`, and diagnostics.

### Diagnostics (USB only)

| Request | Reply |
| --- | --- |
| `diag.state` | `diag.state` with the portable state below, flattened |
| `diag.act {act}` | Applies a semantic action from the portable contract and replies with `diag.state` |
| `diag.shot` | SHOT frames carrying the 468 × 466 RGB565 canvas as M5GFX stores it, then `diag.shot.end {w,h,bytes}` |

Evidence lines go out as LOG frames prefixed `AD_`: `AD_HARDWARE`, `AD_TOUCHMAP version= generation=`, `AD_SPEAKER`, `AD_MIC`, `AD_WIFI`, `AD_SCREEN <name>`, `AD_EVENT`, `AD_SOUND beep`, `AD_FPS`, `AD_STACK`.

### Limits

The hub caps every outgoing field so that a JSON frame stays under 2048 bytes.

| Field | Cap |
| --- | --- |
| id | 47 |
| name | 39 |
| harness | 11 |
| turn text | 60 |
| summary | 160 |
| question text | 199 |
| option | 79 |
| key and requestId | 79 |
| questions per request | 4 |
| options per question | 6 |

When a question at these caps would still reach 2000 bytes, the hub shortens every option, then every prompt, evenly with an ellipsis, and drops trailing questions last.
The hub stores only printable text with control characters removed. The device truncates by codepoint when a field would overflow its own buffer.

### Timing

| Constant | Value |
| --- | --- |
| Device hello without / with a session | 2 s / 15 s |
| Device session down after silence | 15 s |
| Hub ping | 5 s |
| Hub reopens the port after silence | 20 s |
| Hub rescans for an Espressif board (vendor `303a`) | 2 s |

### Voice

- **Format:** 16 kHz, signed 16-bit little-endian, mono. The device streams PCM live, at most 1024 bytes per frame, and stops at 10 minutes.
- **Stalled cable:** a PCM write that fails aborts the take with `voice.abort {why: "cable stalled"}`.
- **Half-duplex speaker:** the Stopwatch speaker and microphone share the codec. The device stops the speaker before recording and plays no sound while recording.
- **Transcription:** the hub wraps the PCM in a WAV file and runs `AGENT_DIAL_STT`, a command template with `{wav}` and `{lang}` placeholders, whose standard output is the transcript. With no command configured, the hub answers `voice.error` `Set AGENT_DIAL_STT on your computer`. The audio file is deleted afterwards.
- **Routing:** a take addressed to a session goes to that session. An unaddressed take, started from the Overview, goes to the session with the most recent activity that has `prompt`. With none, the hub answers `voice.error` `No agent to send that to`, which is upstream's wording.
- **Empty take:** an empty transcript answers `voice.error` `Didn't catch that`.

## Controls

Hold the Stopwatch with the lanyard down.
Touch works as it does on upstream's dial.
The pushers use the default ESPtember grammar, mapped onto upstream's on-screen controls:

| Stopwatch | Upstream equivalent | Effect |
| --- | --- | --- |
| left (BtnA) click | ‹ chevron, or a horizontal swipe | Previous session; from the Overview, the last session |
| right (BtnB) click | › chevron, or a horizontal swipe | Next session; from the Overview, the last session |
| both briefly (Enter) | tapping the Voice button | Start voice for the focused tile, or a routed take from the Overview; while recording, stop and send |
| both held 600 ms (Back) | a BOOT key press | Dismiss a question, ask `Cancel task?` for a working tile with `stop`, abort a recording, or close the drawer or Settings |

- A chord joins within 80 ms and overlaps for at least 80 ms.
- A chord consumes both buttons' clicks, and Enter never fires after a hold.
- There are no single-button holds.
- Upstream's 800 ms BOOT hold toggles the screen. It is not ported: the Stopwatch's power key belongs to its power chip, and the dial sleeps on its own.
- Any input while the screen is asleep wakes it and is swallowed, exactly as upstream swallows the waking touch.

Touch, from upstream's `touch.c`:
- A swipe is 55 px of mostly horizontal or mostly vertical travel.
- A tap stays within 30 px for under 700 ms.
- A swipe down that starts in the top band (44 px on a tile, 90 px elsewhere) opens the drawer.
- A swipe up that starts at y ≥ 400 toggles between the tile and the Overview.
- A tap anywhere stops a recording.
- Swipe direction follows Settings.

## Portable state

`tests/contract.json` models three session slots (`a`, `b`, `c`).
The device holds 16 with the same rules.

Per slot:

- `<slot>_state`: `none|idle|working`, default `none`.
- `<slot>_asking`: bool. A question or approval is open.
- `<slot>_unread`: `none|done|question`. The drawer row, if any.
- `<slot>_stop`, `<slot>_prompt`: bool. Declared capabilities.

Global:

- `connected`: bool. The device has a hub `welcome` or a direct client.
- `screen`: `overview|agent|question|drawer|confirm|voice|settings`, default `overview`.
- `focus`: `none|a|b|c`. The tile the carousel rests on.
- `voice`: `off|recording|routing`.
- `voice_target`: `none|a|b|c|routed`.
- `awake`: bool, default true.
- `badge`: 0–3, the number of drawer rows.
- `emit`: the outbound message of the action (`focus a`, `agent.open a`, `answer a`, `turn.stop a`, `voice.begin a`, `voice.begin`, `voice.end`, `voice.abort`, or empty).
- `sound`: `none|beep`.
- `toast`: the toast text the action raises, or empty.

Host actions:
- `welcome`, `silence_15s`
- `{agent, id, stop, prompt}` and `{gone, id}`
- `{turn_started, id}`, `{turn_done, id}`, `{turn_error, id}`
- `{summary, id, quiet}`
- `{question, id}`, `{question_close, id}`
- `{transcript, id}`, `voice_error`

User actions: `left`, `right`, `enter`, `back`, `tap`, `confirm_yes`, `confirm_no`, `answer`, `swipe_down_top`, `swipe_up_bottom`, `{open_row, id}`, `open_settings`.

Clocks: `idle_5m` and `advance_60s`.

## Behavior

1. **Connection.**
   - `welcome` connects.
   - `silence_15s` disconnects and clears every session, drawer row, question, and open overlay, then returns to the Overview. A recording in progress is dropped without sending anything, because nothing is listening.
2. **Sessions.**
   - `agent` adds a session as `idle` or updates its capabilities.
   - The first session to arrive becomes the focus without emitting `focus`. Programmatic moves never echo.
   - `gone` removes a session. If it held focus, focus moves to the next session in slot order, or to `none`.
   - A removed session's question closes. If its question or confirm screen was up, the dial returns to the tile.
3. **Paging.**
   - On a tile, left and right step through present sessions in slot order with wrap-around.
   - Each step emits `focus <slot>` and clears that session's `done` row.
   - From the Overview, either pusher, and `swipe_up_bottom`, go to the focused tile. Arriving on a tile emits `focus` and clears its `done` row.
   - Paging does nothing on the question, drawer, confirm, voice, and Settings screens.
4. **Turns.**
   - `turn_started` marks a session working. The tile shows upstream's rotating verb (`Working`, `Brewing`, `Cooking`, `Churning`, `Frosting`, `Simmering`, `Tinkering`, `Conjuring`, `Composing`, `Percolating`, `Wrangling`, `Hatching`, `Concocting`, `Puttering`, changing every 6 s) with elapsed time, as in `Cooking… 34s`.
   - While a question is open, the tile reads `Waiting for you` instead.
   - `turn_done` returns the session to idle, silently.
   - `turn_error` returns it to idle and toasts the message (`turn error` in the contract).
5. **Summaries.**
   - A summary returns the session to idle and replaces its recap card.
   - It beeps, as upstream always does, unless voice is recording.
   - It adds a `done` row to the drawer unless the summary is `quiet` or the dial is awake on that session's tile.
   - A `question` row is never replaced by a `done` row.
   - A summary arriving while the dial sleeps wakes it on the drawer.
6. **Questions.**
   - A question marks the session asking, adds a `question` row, wakes the dial, and beeps unless voice is recording.
   - It emits `agent.open <slot>`, which is upstream's `reason: "question"`.
   - If no question screen and no recording are up, it focuses that session and opens its question screen.
   - Otherwise it waits in the drawer.
   - Answering (single tap, or Done for multi-select) emits `answer <slot>`, clears the question and its row, and returns to that tile.
   - Back dismisses the question to the tile. The question and its row stay.
   - `question_close` clears it and returns an open question screen to the tile.
7. **Stop.**
   - Back on a working tile whose session has `stop` opens `Cancel task?`.
   - `confirm_yes` emits `turn.stop <slot>` and optimistically marks the session idle. `confirm_no` and Back return to the tile.
   - Without `stop`, Back toasts `Can't stop this from here`.
8. **Voice.**
   - **Starting:** Enter (or tapping the tile's Voice button) on a tile starts recording to that session when connected and the session has `prompt` and no open question. It emits `voice.begin <slot>`. From the Overview, with at least one session, it emits `voice.begin` for a routed take.
   - **Refusals:** a session without `prompt` toasts `Can't send to this harness`. Disconnected, it toasts `Not connected`.
   - **Sending:** Enter or a tap while recording emits `voice.end` and shows the routing sparkles.
   - **Aborting:** Back while recording emits `voice.abort` and returns to the previous screen.
   - **Routing:** a transcript focuses its session and keeps the sparkles until that session's `turn_started`, then shows its tile. `voice_error`, or 60 s without a turn starting, releases the overlay. The `voice_error` message is toasted (`voice error` in the contract).
   - Voice keeps the dial awake.
9. **Drawer.**
   - `swipe_down_top` from a tile or the Overview opens the drawer. Back or a background tap closes it.
   - A row tap emits `agent.open <slot>` and focuses that session.
     - A question row opens the question screen, and the row stays until answered.
     - A done row opens the tile and clears the row.
   - `badge` counts rows, and the Overview bell shows it.
10. **Overview.**
    - Shows the session count, `N working` or `All idle`, and three buttons: inbox, voice, and settings.
    - `open_settings` opens Settings, and Back returns.
    - Settings holds: Voice language (en, vi, es, fr, ja, it); Swipe (Natural or Reversed); Brightness; Touch calibration; and Version.
11. **Sleep.**
    - `idle_5m` turns the panel off unless voice is active or the dial rests on a working tile.
    - Any user action while asleep only wakes it.
    - Questions and summaries wake it.
12. **Sound.**
    - One cue, from upstream: three 2 kHz square tones, 80 ms each with 60 ms gaps, at most once per second.
    - The device synthesizes it after stopping the microphone.
    - Settings changes beep too; the contract does not model that.

- The working line is at y = 204.

**Everything else**

## Failure behavior

- **No hub and no pairing:** adapters stay quiet and the harness is unaffected. An adapter that finds neither retries every 5 s.
- **Unplugged, or the hub quit:** after 15 s the dial clears to `Not connected` and keeps greeting every 2 s. Direct Wi-Fi sessions continue.
- **Device reset:** the hub resends the roster on the next `hello` from a new boot.
- **Bad frames:** they are stepped over and counted, never fatal. Unknown `t` values are counted.
- **A foreign board** (wrong magic, or `product` other than `agent-dial`): the hub releases its port and retries it after 60 s.
- **Flashing:** `agent-dial release` frees the port for 30 s. Flash app-only at `0x10000`.
- **A hook or extension process exits with an open question:**
  - The hub closes that question on the dial.
  - A Claude Code `PermissionRequest` hook that gets no answer within 590 s exits without a decision, and Claude Code falls back to its own prompt.
- **Claude Code's `PermissionRequest` input carries no `tool_use_id`** (observed on Claude Code 2.1.283). The adapter cannot match a later `PostToolUse` to an open approval, so an approval answered in the terminal stays on the dial until the hook exits or its 590 s wait ends.
- **Another hub on vendor `303a`:** Day 34's pi-pet hub opens any Espressif board. Pause it (`{"t":"pause"}` on `~/.pi-pet/hub.sock`) before this hub or a flasher needs the port.
- **Redaction:** activity lines and summaries are redacted before they leave the harness:
  - `Bearer` and `Basic` credentials;
  - values of arguments or assignments whose key contains token, secret, password, passwd, api-key, or auth.
- **Reducing detail:** `AGENT_DIAL_DETAIL=0` reduces activity lines to the tool name and summaries to `Done`.
